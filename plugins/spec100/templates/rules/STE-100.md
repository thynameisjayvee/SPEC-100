# STE-100 structural and architectural standard

SPEC-100 identifies the specification; STE-100 names the standard.

- All agents must follow ASD-STE100 Simplified Technical English for all applicable technical communication.
- Keep project context, append-only learnings, the three mandatory rules, project-specific subagents, four lifecycle skills, and topic artifacts under `harness/`.
- Keep every project-owned file and directory explicitly indexed in `harness/project-index.md`. Link that file from the managed root `CLAUDE.md` section. Do not import it. Include tracked and unignored project entries and harness assets. Exclude Git internals, dependencies, caches, and build output. Index symlinks as leaves.
- Preserve instructions outside the managed root section and all unrelated Claude settings. Canonical skill and agent documents live under `harness/`; native Claude integration uses relative symlinks.
- Research belongs at `harness/thoughts/<topic>/research_<name>.md`; plans at `harness/thoughts/<topic>/plan_<name>.md`. Keep review evidence, revisions, UAT attachments, and run records within the same topic.
- Each participating subagent must supply concise destination, reason, cost, next-action, and environment checkpoints before executing. Log operational summaries, never private reasoning.
- Use the primary working directory. Create a Git worktree only when explicitly requested. Do not overwrite unrelated user changes, reset a dirty checkout, merge, deploy, or create a PR automatically.
- Software work requires baseline and pre-PR verification, independent AI/security review, two verifier votes per finding, risk assessment, high-risk human approval, detection and rollback steps, and applicable UAT screenshots.
- The initial review counts as round one. Stop after three total review rounds. Unresolved or disputed findings leave a blocked handoff. Never reset the run to evade the cap or manufacture passing evidence.
- High-risk actions require explicit approval before acting. Changed code or plans invalidate affected evidence and approvals. Unknown risk is high until assessed.
- UAT may be skipped only with an explicit reason it is inapplicable. Unavailable tooling and failing tests do not make UAT inapplicable.
- Record lessons through the runtime append operation. Run `/spec100:check` before claiming completion.
